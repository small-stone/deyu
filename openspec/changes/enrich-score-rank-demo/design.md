# Design

## Context

在用界面是 `components/tabs/teacher-board` 和 `components/tabs/admin-rank`。班级预览走已注册的 `pages/teacher/board`。`pages/admin/rank` 等页未进 `app.json`，但是同一套条长算法的拷贝。样式以 `miniprogram/app.wxss` 为准（`--coral: #E07A5F` 已用于分布图低分段和 `.score.lo`）。`styles/ui.wxss` 是一份未引用的拷贝。

个人条宽现在是 `Math.max(8, round(abs(score) / maxAbs(当前列表) * 100))`。低分关注只有 -8、-5、12 时，`maxAbs` 为 12，所以 12 分满条，|-8| 比 |-5| 更长。高分榜的 `maxAbs` 是 96，同一分数换一张榜长度就变了。

`school.personHigh` / `personLow` 只有姓名字符串，没有学生 id。管理员打开班级时会写 `state.currentClassId`，班主任当前班会被预览改掉。`getClassBoard(classId)` 已经能按 id 取班，调用方没有传入。

## Goals / Non-Goals

**Goals:**

- 一条共享的个人分颜色和条宽规则，班主任看板、全校个人榜、学生详情用同一实现。
- 排行行带着学生 id 或班级 id 跳转，管理员预览不改班主任当前班。
- 351、443、551、244 各自有可点名的花名册和五段分布；全校个人榜从学生记录推导，而不是再维护一份对不上的短名单。

**Non-Goals:**

- 不重算 352 的分布段和既有分数。
- 不把全校 756 人的总分布改成「现有花名册之和」。
- 班级均分条继续相对最高均分缩放，只补上 &lt; 40 的橙色。
- 不改家长分数环，不把花名册点击从加减分改到详情。

## Decisions

### 1. 个人条宽用固定 0–100 刻度

`personalBarWidth(score)`：分数 ≤ 0 时宽度为 8（现有最短可见条）；否则 `min(100, max(8, round(score)))`。100 分即满条。12 分约为 12% 宽，-8 与 -5 都是最短条，因此 -8 不会长过 -5，同一分数在高分榜和低分关注里一样长。

备选是把负数映射到「-20～100」上，让 -8 和 -5 长度不同。那仍然会让用户觉得低分条在互相比较「谁更负」，和「分数越高条越长、100 分为满」不一致，所以不用。

班级均分保持 `score / 榜首均分 * 100`。均分都在 60 以上，不存在绝对值缩放问题。

### 2. 颜色阈值与分布图对齐，边界用「小于 40」

`isLowScore(score)` 为 `score < 40`。橙色用现有 `--coral`，绿色用 `--brand`。恰好 40 分保持绿色，与花名册 `score < 40` 和「40 分以下」一致。分布图上的「0–40」仍是分段标签，不把恰好 40 分的条改成橙色。

在 `app.wxss` 给 `.bar .fill.low` 和排行分数 `.lo` 使用 `--coral`。`styles/ui.wxss` 同步这两条，避免以后拷回去时丢规则。学生详情上的当前分用同一判断。

### 3. 非 352 班用「可点名花名册 + 由花名册生成的分布」

每个非 352 班增加约 8 名学生，覆盖 80 分以上、中间分段，以及 40 分以下（含至少一名负分或个位数，以便低分榜有跨班数据）。班级卡片上已有的最高/最低姓名必须落在该班花名册里：351 周启 / 吴桐，443 钱进 / 刘可，551 何佳 / 孙悦，244 郑好 / 冯帆。这些班的五段分布和 `studentCount` 由该班学生现算，图表不再是空数组。

352 的学生分数和写死分布不动。全校总分布、全校均分、班级数保持现有总览数字。

`personHigh`、`personLow`、`lowAttention` 改为由全部学生推导（高分取降序前 8，低分取升序前 8），每行带 `studentId` 和 `classId`。这样榜会超过 3 行，并且点得中人。给低分关注里会出现的学生补若干条加减分记录，详情时间线不为空；352 只追加记录，不改分。

### 4. 详情页与跳转

新增 `pages/common/student-detail/index`，查询参数 `id`，注册进 `app.json`。页面展示姓名、班级、学号、当前分（按决策 2 着色）和 `timeline-list`。没有记录时时间线为空，不报错。

班级行跳到 `/pages/teacher/board/index?preview=1&classId=<id>`。预览页只把 `classId` 传给 `getClassBoard`，不写 `currentClassId`。总览和班级列表里现有的「打开班级」改为同一查询参数。

个人行 `bindtap` 打开学生详情。班主任看板行已有学生 id；全校个人榜改用推导结果里的 `studentId`。

条宽、颜色、点击在 tab 组件和仍保留的页面拷贝（`pages/teacher/board`、`pages/admin/rank`、`pages/admin/overview`、`pages/admin/classes`）里都走上述入口，避免未注册页以后接回路由时行为不同。

## Risks / Trade-offs

- [非 352 班的 `studentCount` 从约 40 变成花名册人数] → 总览班级卡片人数变小，但和看板分布一致。全校「756 人」不跟着改，总览总数仍是设计稿量级。
- [-8 与 -5 的条一样短] → 这是固定刻度的结果，数字本身仍显示 -8 和 -5。不再用条长区分两个负分。
- [352 分布人数仍大于实际花名册] → 按范围保留。不要顺手把 352 分布改成 6 人。
- [管理员与班主任共用一份内存 store] → 预览禁止写 `currentClassId`。若仍写入，班主任「本班」会变成刚点开的班。

## Migration Plan

只改本地演示数据与页面。无需迁移云数据。回滚时恢复 `demo-store` 种子、去掉详情页路由，并撤回条宽与跳转即可。
